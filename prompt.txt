# Functional Requirements

## User Authentication

Implement:

* User Registration
* User Login
* User Logout
* JWT Authentication
* Protected Routes
* Password Hashing using bcrypt

Store users in SQLite.

---

## PDF Management

Allow users to:

* Upload PDFs
* View Uploaded PDFs
* Delete PDFs

Requirements:

* Maximum 5 PDFs per user
* Support approximately 800 pages total
* Store metadata
* Automatically update indexes after uploads
* Automatically rebuild indexes after deletions

Metadata:

* User ID
* Filename
* Upload Timestamp
* Page Number

---

## PDF Processing

Use:

PyPDFLoader

Extract:

* Text
* Metadata
* Page Numbers

Chunking Configuration:

chunk_size = 1200

chunk_overlap = 200

Store page numbers in chunk metadata.

---

## Embeddings

Use:

OllamaEmbeddings

Model:

nomic-embed-text

Requirements:

* Persist embeddings
* Load automatically at startup

---

## Vector Search

Use:

FAISS

Requirements:

* Persist FAISS indexes
* Load indexes at startup
* Incrementally update indexes after uploads
* Rebuild indexes when documents are deleted

---

## Keyword Search

Use:

BM25Retriever

Requirements:

* Build BM25 indexes
* Rebuild BM25 indexes after document changes

---

## Hybrid Retrieval

Implement:

EnsembleRetriever

Configuration:

FAISS:

* top_k = 5

BM25:

* top_k = 5

Weights:

[0.7, 0.3]

Deduplicate results.

Final Context:

8 chunks maximum.

---

## Context Handling

Since phi3 has context limitations:

* Retrieve 8 chunks maximum
* Remove duplicate chunks
* Truncate context intelligently if necessary
* Preserve citations after truncation

---

## Chat System

Implement:

* Multi-turn conversations
* Chat history
* Persistent storage

Flow:

User Question
↓
Hybrid Retrieval
↓
Context Assembly
↓
Phi3 Mini
↓
Answer

Store history in SQLite.

Store:

* User Message
* Assistant Message
* Timestamp
* User ID

---

## Source Citations

Every answer must include citations.

Format:

Sources:

* filename.pdf (Page 15)
* filename2.pdf (Page 23)

Sources must come from retrieved chunks.
